# 通知中心导航与页面标题

## 左侧导航

- 左侧导航使用“通知中心”作为通知入口，不显示独立的“未读”导航项。
- “通知中心”入口右侧仅显示当前未读通知数量。
- “工作”和“远程设备”入口右侧显示各自分类的未读数量。
- 主窗口顶部居中提供下滑式 Toast，用于提示通知动作的执行结果，文字过长时截断显示；Toast 使用深色圆角胶囊，左侧为绿色对勾图标，4 秒后自动收起，也可以点击右侧关闭按钮立即收起。
- “微信分析”入口右侧不显示数量，改为显示 QwenPaw Agent 登录状态徽标：已登录为绿色 `#16A34A` 背景加白色“✓”，未登录为浅红 `#FDECEA` 背景加“✕”，鼠标悬停显示当前分析 Agent 或登录引导。
- 左侧导航顺序为“通知中心”“工作”“微信分析”“联系人管理”“App”“远程设备”和“设置”。
- 主导航不显示“关于”；进入设置后，设置壳层覆盖主页面，并用“常规”“微信分析”“通知”三级菜单替换主导航。
- 设置壳层左上角提供返回入口，返回进入设置前的主页面。
- “联系人管理”页面直接嵌入主 App，原联系人管理页面的功能继续通过内部左侧 Tab 切换。
- 导航尾部徽标（数量与登录状态）统一使用 `count-badge` 的 20×20 px 圆形样式，内容水平、垂直居中。
- “通知中心”“工作”和“微信分析”使用 `Assets/icons/nav-notifications.svg`、`nav-work.svg` 和 `nav-wechat-analysis.svg` 对应的 20×20 细线图标；运行时使用相同几何的 Avalonia `Path`，图标颜色跟随导航文字颜色。
- 导航按钮内容使用横向 Stretch、垂直 Center；每个导航行的图标、文字和数量徽标均垂直居中，图标列中的字符图标水平居中。
- 导航行的图标列与文字列之间保持 8 px 间距，避免图标与文字贴合。
- 设置入口使用 `Assets/icons/nav-settings.svg` 的 SVG 几何；运行时使用相同几何的 Avalonia `Path`，图标颜色跟随导航文字颜色。

## 通知卡片状态

- 通知卡片标题右侧显示状态文字：未处理且已读时显示灰色“已读”，通知已解决时显示绿色“已处理”，两者不同时出现。
- 通知已解决时卡片隐藏全部操作按钮，使用浅绿底色和普通已读样式的灰底区分。
- 已解决卡片的状态文字取自动作写入的处理方式标注：`confirm-todo` 显示“已加入TODO”，`reject-todo` 和其他处理显示“已处理”。
- 任何通知动作执行后，桌面端都用顶部 Toast 反馈结果，不再追加一条新的通知；执行“此前已处理”的动作同样只提示结果，不重复改变 TODO。

## 页面标题

- 通知中心、微信分析和远程设备共享主页面顶部页头；设置使用独立壳层和分类页头；工作页使用内部 Tab，不显示主页面全局页头。
- 通知搜索、通知菜单和更多操作只在“通知中心”页面的页头显示。
- 其他页面的页头不显示通知中心工具栏。
- 通知中心内部仍提供“全部通知”“未读”“已读”筛选。

## 工作页通知与已读同步

- “工作”页中的工作类通知提供直接的“标记已读”操作。
- 标记单条或全部已读后，通知中心和工作页中的卡片会立即更新已读样式、状态文字和操作按钮。
- “工作”页使用两个 Tab：TODO Tab 占满工作区域，以 Trello 风格看板展示列表和卡片，提供搜索、状态/公司筛选、手动顺序/优先级等排序、卡片跨列表移动、列表排序、卡片与列表更多菜单及详情编辑；工作通知 Tab 独立展示未读普通通知或仍需操作的通知，并提供“查看全部通知”进入通知中心。

## 工作页卡片加载

- TODO Tab 看板中，每个列表首屏只加载前 50 张卡片（不足 50 张时全部加载）；滚动接近列底部剩余不足 120 px 时按 50 张一批继续加载，直到全部显示。
- 列表头部“N 张卡片”显示该列表全部卡片数，包括尚未加载的卡片。
- 切换筛选、排序、搜索或公司条件后，列表整体重建，每个列表的加载进度重置为首批 50 张。
- 卡片数据在页面加载时已全部读入内存，分批加载只延迟卡片界面元素的创建；拖拽卡片到列表空白处时按全部卡片的真实末尾位置追加，而不是已加载部分的末尾。

## 通知搜索

- 进入“搜索通知”页面后，输入关键词不会自动提交搜索。
- 按 Enter 或点击输入框右侧的放大镜按钮均执行搜索，两种入口使用同一个 `SearchNotificationsCommand`。
- 搜索范围覆盖通知标题、正文、来源、分类和级别。

## 通知加载

- “全部通知”“未读”“已读”和工作页的“工作通知”首次均只查询最近 100 条，滚动接近列表底部时继续加载更早的 100 条。
- 通知中心的三个筛选共用同一套查询逻辑，但切换筛选或重新搜索时分别从最新记录重新开始。
- 数据层按 `created_at DESC, id DESC` 排序，并以最后一条记录的 `created_at + id` 作为下一批游标；加载期间新增通知不会导致后续批次重复或漏项。
- 工作通知在 SQLite 查询中直接限制为未解决的工作类通知，并只保留未读通知或仍有操作按钮的通知，不在内存中对普通通知页二次截取。
- 列表使用虚拟化控件，仅为可见区域创建界面元素；当没有更多记录时停止触发后续查询。
